# ADR-001：收藏星标语义——paged 保持逐分 P 挑歌，三处入口取消行为统一

- 日期：2026-09-11 ｜ 状态：已采纳（经一次验收反转后定稿） ｜ 版本：v2.0.1
- 决策人：项目所有者

## 背景

用户实测投诉（Q3-2）：「歌曲详情页的收藏按钮、歌词页的收藏按钮、歌单页的收藏按钮与真实收藏夹不统一」。排查结论：

1. **三处取消行为互不相同**：行内星 `POST /songs/{id}/uncollect` 只动本地（单视频留下幽灵行：应用里没了、B 站收藏还在，且 `playlist_id=0` 后 sync 永远不再管它）；播放条星取消单曲走 `DELETE /songs/{id}` 连 B 站一起取消；播放条星取消 paged 弹确认后删整张专辑。
2. paged 目录态（#37）与 sync「B 站收藏夹为真相源」存在张力，被误判为投诉根因。

## 决策过程（两次）

- **第一版（被验收否决）**：拍板选「星 = B 站收藏」——paged 导入全行点亮、曲库 = 收藏夹完整镜像、paged 取消 = 整张专辑移除。实施后用户 web 验收即推翻：**「不对，多p不是让你全部星星，是收藏的才星星。」**
- **终版（采纳）**：#37 的逐分 P 挑歌是刻意设计，目录态保留；本轮真正要修的是幽灵态与三处入口不一致。

## 终版语义（已实施）

| 容器 | 点星 | 取消星 |
|---|---|---|
| 无专辑（单视频/试听入库） | 该行点亮 + B 站收藏 | **删行 + 取消 B 站收藏**（与 DELETE /songs/{id} 一致，幽灵态根除） |
| paged（多 P 专辑） | 仅点亮该行（B 站视频收藏导入时已成立） | **仅该行退目录态**，B 站收藏与容器都不动（可再点星收回） |
| series（合集） | 该行点亮 + B 站收藏该视频 | 同视频行退目录态 + 取消该视频收藏（容器保留） |

三处入口（播放条星/歌词页星/行内星）统一走 `POST /api/songs/{id}/uncollect`，服务端按容器分流；「整张专辑移除」只保留在专辑详情页的删除按钮（显式意图处）。

## 教训

把「与真实收藏夹不统一」过度解读成了「星必须镜像 B 站视频级收藏」。实际上用户要的是：**挑歌的自主权（逐分 P 星标）+ 行为的一致性（三处入口同一语义）**，而不是显示口径的全面对齐。方案对比时缺了一个「paged 显示维持目录态、只修行为」的中间选项供拍板，导致第一版做过头、验收返工。

## 数据修复（本机一次性，2026-09-11）

第一版「全点亮」代码在验收期间运行过，懒物化把当时打开的 paged 专辑行全部以 `collected=1` 建出（303 行，created_at 均为当日 12:41，无任何灰色行=无手动挑歌混杂）。代码回退后脏数据留在库里，已就地修复：

```sql
UPDATE song SET collected=0, playlist_id=0
WHERE album_id IN (SELECT id FROM album WHERE kind='paged') AND collected=1;
-- 影响 303 行；修复后曲库仅剩单视频真收藏（19 首）
```

不随版本发货：手机端从未运行过全点亮构建（若曾安装 898a93bd 那个作废包并出现全亮，对手机库执行同一条 SQL 即可）。
