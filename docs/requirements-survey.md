## 第二部分：候选需求打分（17 项，每项 0–5 分）

> 打分口径：**0 = 永远不要，1 = 无所谓，3 = 有了更好，5 = 没有它会痛**。来源竞品见对标文档 §7。

### 高契合组

| 编号 | 需求 | 说明 | 得分 |
|---|---|---|---|
| A1 | 队列稳定性承诺 | 收藏夹连播不断、CDN 失败自动换源自愈，升格为「承诺」并进回归测试 | |
| A2 | 串流细节打磨 | 切换更快、进度更准、设备列表过滤噪音 | |
| A3 | 音质档位放开 | 320K/Hi-Res（需大会员）；前置修复 BUG-006 | |
| A4 | 音量均衡 + gapless | B 站各视频响度差异大，歌与歌之间不再忽大忽小 | |
| A5 | 漫游电台 | 以收藏夹/当前歌为种子自动续队列，「听完不知道听啥」的解法 | |
| A6 | 弱网自动降档 | 网差时自动切低码率不断播，恢复后回升 | |

### 中契合组

| 编号 | 需求 | 说明 | 得分 |
|---|---|---|---|
| B1 | 自动连接开关 | 自动串流保留为默认，但给个「今天别自动接管」的退路 | |
| B2 | mini 播放器 / 托盘遥控 | 桌面端缩小成小窗/托盘控制 | |
| B3 | 稍后再看 / 历史入口 | 不进收藏夹的内容也能顺手听 | |
| B4 | 桌面歌词 / 逐字歌词 | 桌面悬浮歌词；逐字卡拉OK | |
| B5 | 歌单导入增强 | 粘贴整段分享文本，批量识别成歌单 | |
| B6 | 轻量听歌报告 | 「本周听了什么」，本地数据即可，零算法 | |
| B7 | UP 更新 / 收藏夹更新提醒 | 内容发现的最小形态：关注的 UP 发新歌知道一声 | |
| B8 | 广域网访问引导 | 出门也能连家里：把 Tailscale 方案做成内置引导 | |
| B9 | iOS / PWA 增强 | iPhone 上目前只有浏览器体验 | |
| B10 | 歌词质量看板 | 哪首没歌词、为什么，一眼可见 | |
| B11 | 多用户 / 家庭共享 | 重构账号模型，成本最高；竞品调研认为与定位冲突 | |

## 第三部分：关键取舍题（5 题，二选一须给理由）

> 这些题没有全都要的选项——按惯例，拍板时放弃的那半边也要写清楚。

**T1 离线之争（两份分析的唯一真分歧）**
`product-analysis.md` 把「听过的可离线」列为 P1（通勤场景）；竞品调研判为低契合（同类项目全家做下载=红海，且与「不存音频、零数据托管」的定位根本冲突）。
□ a. 维持纯在线，通勤问题不归这个产品管
□ b. 做轻缓存：只缓存最近听过的 N 首，无下载管理界面，可一键清空
□ c. 做完整下载/导出（等于改定位，需重写 README 与边界声明）
理由：

**T2 音质的前提**
放开 320K/Hi-Res 需要大会员账号，且必须先修 BUG-006 选档逻辑。
□ a. 我是/愿意开大会员，音质档位值得做
□ b. 不开会员，192K 够了，这条出池
□ c. 先只修 BUG-006（把选档逻辑修对），档位放开等有会员再说
答：

**T3 发现的投入深度**
「发现歌」目前全靠自己搜 + 播放时搭车采集。
□ a. 投入发现：A5 漫游电台 + B7 更新订阅（v2.1 主线候选）
□ b. 保持纯手动，把精力全押播放与串流质量
理由：

**T4 随身化**
局域网限定意味着「它只是家里的播放器」。
□ a. 接受，家里够用，广域网出池
□ b. 做 B8 引导页（教用户挂 Tailscale，产品本身不碰公网）
□ c. 内置中继/穿透（成本与安全面大增，需专项方案）
答：

**T5 iOS**
□ a. 我没有/不用 iPhone 听歌，出池
□ b. PWA 增强够（加 manifest/图标/媒体会话适配）
□ c. 值得开一个原生壳项目（参考 Android 的做法，工作量 1–2 周）
