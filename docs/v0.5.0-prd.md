# BiliMusic v0.5.0 升级计划 PRD

> 版本：v0.5.0 ｜ 状态：草案（待评审）｜ 关联：v0.4.0 已于 2026-09-09 发布并验收通过
> 原则：**把 B 站一切可收藏为歌单的内容形态统一成「合集容器」，逐作品收藏，语义与 B 站收藏夹哲学一致。**

---

## 1. 背景与目标

v0.4.0 引入「合集 = 容器」：多 P 视频导入为歌单式容器，子作品用星标逐个收藏。这解决了「收藏一次 = 50 首全进曲库」的痛点。

但 B 站除了「多 P 视频」，还有另一种内容形态 —— **合集/列表（系列）**：一个 UP 主把多个**独立视频**凑成一个系列（`space.bilibili.com/{mid}/channel/collectiondetail?sid=<id>`）。它和多 P 的区别在于：
- 多 P：一个视频，多个分 P（我们已做）。
- 系列：多个独立视频，每个可有自己的多 P（**尚未实现**）。

**本版本目标（一句话）**：让 B 站跨视频**系列**也能变成一个「合集容器」，点开看到所有作品、逐作品收藏；同时修复 v0.4.0 遗留的「同步时合集反复导入」一致性问题。

**成功标准**：
1. 粘贴/识别一个 B 站系列链接 → 出现「合集」容器（含全部子作品）。
2. 容器内逐作品用星标收藏 → 只进曲库收藏的那一首。
3. 删除合集 → B 站侧对应收藏批量取消（失败后台自愈）。
4. 同步收藏夹后，不再出现「合集视频被反复导入」。
5. 多 P 视频、单曲、收藏夹三种存量形态**行为不回归**。

## 3. 功能需求

> 优先级：**P0** = 本期必须；**P1** = 尽量；**P2** = 按需。

### 3.1 链接解析（P0）
- `link_parser` 识别 `https://space.bilibili.com/{mid}/channel/collectiondetail?sid=<id>`，产出 `SeriesRef(sid)`。
- 识别分享文本里的系列链接与「合集」「系列」关键词抛出。

### 3.2 数据模型（P0）
- `Album` 表 `kind` 增加 `"series"`；`source_bvid` 存 `sid:<id>`（区分 paged 的 bvid）。
- 曲目行 = 系列内每个视频；视频若为多 P，其曲目复用 paged 语义（每个分 P 一行，`track_no` 排序）。
- SQLite 迁移：扩展 kind 取值即可（无需新列，`source_bvid` 加前缀区分）；如需要则加 `series_sid`。

### 3.3 拉取与导入（P0）
- 系列视频列表接口：`/x/polymer/web-space/seasons_archives_list?mid=..&season_id=..&page_num=..&page_size=..`。
- **频控**：串行 + 每请求间隔（>100 视频必分页），失败降级不阻塞；走后台 `ImportTask`，进度按视频数展示。
- 导入语义（区别于多 P）：**系列 = 每个视频各收藏一次**（B 站语义矩阵 series 列）；多 P 视频内的分 P 看作 paged 子专辑。

### 3.4 收藏 / 删除 / 恢复语义（P0 / P1）
| 环节 | 多 P（paged） | 系列（series） |
|---|---|---|
| 收藏同步 | 整视频收藏一次 | 每视频各收藏一次 |
| 删除 | 删专辑=取消该视频收藏；单曲移出=本地 | 删专辑=批量取消收藏（后台自愈）；单曲删除=取消该视频收藏 |
| 换设备恢复 | 收藏夹单行→专辑行→曲目按需回填 | sid 重建+与收藏夹合并；sid 失效退化散曲不丢歌（P1） |
| 逐作品收藏 | 分 P 星标（#37 已做） | 系列内视频星标（复用） |

### 3.5 同步一致性修复（P0 前置，必做）
- **问题**：v0.4.0 把 `library.list_songs()` 默认改为 `only_collected=True`；`sync.py` 用同一查询判断「B 站收藏夹视频是否已在本地」——合集（多P）视频若本地只有未收藏子作品，会被当成「不在本地」而**反复导入/重复打接口**。
- **修法**：同步的 bvid→本地 映射改用全量（`only_collected=False`），或在映射里把「该 bvid 存在 album 容器」也视为「已本地」；补一条同步回归用例。

### 3.6 UI（P0）
- 合集卡（series）复用专辑卡；详情页顶部标注「合集 · N 个作品」。
- 曲目行逐作品星标收藏（空心→实心，复用 #37 的星）。
- 资料库与主页「合集/专辑」区都展示（同 v0.4.0 两处）。
- 导入进度区分「多P 分 P 数 / 系列作品数」。

## 4. 非功能需求

- **风控安全**：系列拉取严格限速 + 失败降级；B 站 412/风控时静默退化为「按需逐个导入」。
- **性能**：超大系列（数百视频）不阻塞 UI；导入任务后台化、可取消。
- **兼容**：v0.4.0 的 `collected` 数据不回滚；旧 `paged` 专辑不受影响。
- **无前端构建**：仍为服务端渲染 + htmx（不引入构建链）。

## 7. 验收标准（怎么验收）

> 逐条给「操作 → 期望」。真机（Android）+ 桌面（macOS/Windows）+ 浏览器三路跑。

### 7.1 功能验收
1. **链接导入**：复制一个系列链接 → 贴进搜索框 → 回车/收藏 → 出现「合集」容器，列表含全部子作品标题/封面/时长。
2. **逐作品收藏**：点开合集 → 每行星标空心 → 点某几个 → 变粉色实心 → **曲库/侧栏计数只 + 对应数量**（不再全量入库）。
3. **整张播放**：合集容器点「播放」→ 顺序播放全部作品；多 P 作品播对应分 P。
4. **删除合集**：容器页「删除」→ B 站收藏夹里该系列对应收藏批量消失（失败后台自愈，本地仍删除）。
5. **同步一致性**：手动「同步」→ 观察任务列表**不再**出现已收藏合集视频的重复导入；任务列表无噪音。
6. **单曲删除**：系列内删单个作品 = 取消该视频收藏；系列里其余不受影响。

### 7.2 回归验收（v0.4.0 行为不回退）
1. 多 P 视频导入为容器：点开逐分 P 星标收藏（#37）。
2. 普通单曲：收藏、播放、歌词、列表功能正常。
3. 收藏夹批量导入（favlist 链接）正常。
4. 移动端：资料库 Tab 进出、UP 详情 dock、通知栏媒体卡片、搜索三分类。
5. 桌面搜索框中文输入法空格选词不被打破（#27）。

### 7.3 自动化门槛（提交前必须绿）
- `python -m pytest -q tests/`（全部通过）。

## 8. 风险与取舍

- **B 站接口频控/风控**（`seasons_archives_list` 对合集/系列可能限流）：限速 + 失败降级 + 重试；必要时退化为「收藏夹/逐视频」路径兜底。
- **sid 公开性**：系列链接可能要求登录/已失效 → 需「未登录提示」与「失效退化散曲」兜底。
- **工作量大头**：频控、sid 失效恢复、超大系列懒物化。
