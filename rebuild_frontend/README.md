# BiliMusic 前端重设计 · 设计稿

> 打开方式：用任意静态服务器起在本目录（ES Module 需要 http 协议）：
> ```bash
> cd rebuild_frontend && python3 -m http.server 8001
> # 浏览器打开 http://localhost:8001
> ```
> 右上角工具条可快速切换 主题 / 登录弹窗 / 播放页 / 任务抽屉（仅为演示用，不属于产品设计）。

## 目录

```
rebuild_frontend/
├── index.html          # 入口（纯静态，无构建）
├── css/
│   ├── tokens.css      # 设计令牌：色彩 / 字阶 / 间距 / 圆角 / 动效 / 双主题
│   ├── base.css        # 重置、按钮、徽标、封面、骨架、空态
│   ├── layout.css      # 应用框架：侧栏 / 顶栏 / 主区 / 移动 Tab
│   ├── components.css  # 曲目行、货架卡、详情头、菜单、弹窗、Toast、滑条
│   ├── player.css      # 播放条 / 全屏播放页 / 队列抽屉
│   └── pages.css       # 首页 / 曲库 / 搜索 / 账号 / 登录 / 任务 / 导入
└── js/
    ├── ui.js           # 图标库（内联 SVG）+ 工具函数
    ├── data.js         # demo 数据（形状严格对齐 PRD §4.13 数据字典）
    ├── views.js        # 各页面渲染（真实实现时把 DB 换成 /api/* fetch）
    └── app.js          # 应用壳 + 交互编排（模拟播放时钟）
```

## 设计策略（参考竞品的取舍）

| 来自 | 借鉴 | 用在本稿 |
|---|---|---|
| **Apple Music** | 大封面、留白、两级字重的层级、无重边框卡片 | 货架卡片只有「图 + 两行文字」；详情页主色氛围背景；播放页居中双栏 |
| **Spotify** | 浏览效率、信息密度、左侧导航 + 歌单树 | 侧栏「导航 + 歌单列表 + 账户」三段；曲库行高 56px 单行可读；悬停才出现的行内操作 |
| **YouTube Music** | 沉浸封面、快捷网格、「视频即音源」语义 | 首页 6 宫最近收藏；播放页主色渐变背景；合集/多 P 作为一等公民 |

**统一的两条规则**

1. **一份导航模型，两种呈现**（修 PRD C-5）：导航恒为 `首页 / 曲库 / 搜索 / 账号` 四项——桌面是左侧栏（中屏折叠成纯图标），移动是底部 Tab，指向完全相同的视图集合。
2. **克制即是高效**：单屏只保留一个主操作（粉色），其余操作收进悬停/`⋯`；用主色渐变做氛围而不是堆装饰；所有列表行在触屏下 ≥ 48px 高。

## 逐条回应 PRD 的已知缺口

| PRD | 问题 | 本稿的处理 |
|---|---|---|
| **D-9** | 手机播放条无进度/歌手 | 播放条改为「封面 + 标题/歌手 + 星标 ｜ 播放/下一首」，顶部贯穿 2px 进度条**所有断点可见**；桌面中栏保留完整 seek 滑条。 |
| **D-14** | 桌面无导出入口 | 顶栏常驻「导入」按钮 + 曲库页顶部导入条 + 账号页导出，三端一致。 |
| **D-16** | 双轨进度 | 全稿只有一套 `.slider` 组件 + 一个时钟源，播放条与播放页共享。 |
| **D-15** | 任务失败不可见 | 任务抽屉保留历史、失败项常驻「重试」按钮。 |
| **#15** | 手机三键顺序 | 统一为 上一首 · 播放/暂停 · 下一首（播放条与播放页一致）。 |
| **#19** | 滑条粉色填充 | `.slider` 用 `--val` 渐变实现，拖动跟手，悬停出圆点。 |
| **#8** | 空格播放 | 已带 IME 防线（焦点在 input/select 不劫持）。 |
| **D-11** | 无障碍 | 卡片/行用 `button`/`tabindex`/`role`/`aria-label`，`:focus-visible` 粉色描边，`pointer:coarse` 下行内操作常显。 |
| **§1 数据主权** | 删除语义要对齐 B 站 | 删除二次确认文案明确写「同步取消 B 站收藏」；合集标注「逐视频收藏」。 |
| **§7.3** | 本地键 | `bmTheme`（扩 system）、`bmPlayMode`、`bmVolume`（新增持久化，修「音量每次回 100」）。 |
| **§10 降动效** | — | `prefers-reduced-motion` 全局降级；移动端 `env(safe-area-inset-*)` 全量适配。 |

## 页面清单

- **首页**：问候 + 最近收藏 6 宫 + 每日精选横幅 + 推荐歌单/流派/合集三层货架
- **曲库**：顶部导入条 + 左列歌单卡（含「新建歌单」显式入口，#7）+ 右列搜索/排序/计数 + 曲目表
- **搜索**：空态 → 关键词三分类（UP 主 / 合集 / 视频）→ 识别链接自动转导入
- **详情**：专辑（paged/series 徽标 + 懒物化「加载剩余 N 首」）、歌单、UP 主（头像主色氛围）
- **账号**：资料卡 + 同步五计数摘要 + 主题三段 + 导出/清缓存/关于
- **浮层**：全屏播放页（封面主色背景 + 双栏歌词）、队列抽屉、任务抽屉、登录弹窗、Action Sheet、Toast

## 与真实后端的对齐点

- `data.js` 的字段名与 PRD §4.13 完全一致（`bvid / duration / albumId / collected / kind / totalPages / materializedPages / folderIds…`），把 `DB` 换成 `fetch('/api/...')` 即可逐页接管。
- 合集星标、懒物化、计数口径（视频级）在 demo 交互里已按 PRD 语义表达。
- 音频播放在此稿用 `setInterval` 模拟；真实实现换 `<audio src=song.audioUrl>`，多分 P 依赖 `audioUrl` 自带的 `?cid=`（§4.11）。
